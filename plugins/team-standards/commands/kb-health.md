# 知识库体检

按 `kb` skill 做一次健康检查，最后输出待处理清单。检查范围：$ARGUMENTS（为空时用宿主 repo 约定的知识库根目录，没有约定就用 `docs/kb/`）

按顺序执行：

1. **定位并回读**：找到知识库根目录，读 `index.md` 和目录结构，报出页面数量与分类分布。找不到知识库时停下来问，不要新建。
2. **跑机械校验**：执行
   ```bash
   python <kb skill 目录>/scripts/kb_lint.py --root <知识库根目录>
   ```
   记录退出码和全部 finding。
3. **核对会过期的内容**：只对下面三类页面做语义核对，不要全库通读：
   - `verified_at` 超过复核期的页面；
   - `status: draft` 或 `review` 且长期未定档的页面；
   - lint 报出的疑似重复对。

   对每一类，读页面正文，再对照当前代码、服务文档或业务规则，判断内容是否仍然成立。判断不了时写明"需责任方确认"，不要猜。
4. **输出报告**，按这四组组织，每条给出文件位置和候选动作（更新 / 降级 / 删除 / 合并 / 补链接 / 补证据）：

   ```markdown
   ## 断链与导航
   ## 孤立页面
   ## 超期未核对
   ## 可能已过时（含疑似重复）
   ```

   每组末尾写一句这一组的整体判断；没有问题的组写"无"。

5. **停下来等确认**：只出报告和候选动作，不修改任何文件。报完列出你建议先处理的三条，等用户挑。

机械校验只提供候选名单，最终判断回到证据。
