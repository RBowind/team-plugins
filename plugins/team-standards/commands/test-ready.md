# 提测

按团队规范做提测前检查，最后生成提测说明。本次改动：$ARGUMENTS

按顺序执行，任何一步不通过就停下来报告，不要继续：

1. **跑测试**：用项目 README 里记录的测试命令跑全量测试。没有测试命令记录的，先停下来问。
2. **自查改动**：按测试规范 skill 里的"提交前自查"清单逐条过，列出每条的结论。后端改动用 team-test-standards-backend，前端改动用 team-test-standards-frontend；前后端都改就两个都过。
3. **生成提测说明**，包含：
   - 改了什么、为什么改（从我的描述和 git diff 提炼，不要编造）
   - 测试结果：跑了哪些、多少条、过没过
   - 自查清单每条的结论
   - 风险点：接口变更、涉及金额权限、没覆盖到的部分

最后把提测说明完整输出，等我确认。
